## Objective
When the server refuses a retire, the refusal message stays visible in that ship's entry until the entry's next send starts or its Cancel is clicked. It stays even when a snapshot refresh changes the ship's status away from `idle`. Today the message is rendered only while the ship is `idle`, so the server's own refusal ("ship X is 'assigned', not idle") vanishes as soon as the snapshot shows the ship assigned, or never appears if the snapshot arrives before the answer.

## Context
`Ship` in `web/src/components/Fleet.tsx` renders `{command.error !== null && <div className="msg-error">…}` inside the `.fleet-retire` form, which is inside `{status === "idle" && (…)}`. The request state itself is fine: `useCommand` keeps it, and it reappears when the ship is idle again. Only the place it is rendered is wrong. Everything else in round 0 passed review and must not change. Components cannot be rendered under `node --test`; the reviewer renders them separately. Affected workflow IDs is `none` because this project has no review suite.

Add this test to `tests/http/page-fleet.test.mjs` (it uses the file's existing imports and `root`; adapt only the names of those existing imports if they differ). The reviewer ran it against the round-0 tree and it fails with "the refusal message is rendered inside the idle-only expression":

```js
test("a refused retire stays visible when the ship is no longer idle", async () => {
  const source = await readFile(path.join(root, "web", "src", "components", "Fleet.tsx"), "utf8");
  const start = source.indexOf('{status === "idle" &&');
  assert.notEqual(start, -1, 'Fleet.tsx has no {status === "idle" && ...} expression around the retire controls');
  let depth = 0;
  let end = -1;
  for (let index = start; index < source.length; index++) {
    if (source[index] === "{") depth++;
    else if (source[index] === "}" && --depth === 0) { end = index; break; }
  }
  assert.notEqual(end, -1, "could not find the end of the idle-only expression in Fleet.tsx");
  const idleOnly = source.slice(start, end + 1);
  assert.ok(idleOnly.includes("Confirm retire"), "the retire controls are not inside the idle-only expression");
  assert.ok(!idleOnly.includes("msg-error"), "the refusal message is rendered inside the idle-only expression, so it disappears when the ship's status changes");
  assert.ok((source.slice(0, start) + source.slice(end + 1)).includes("msg-error"), "Fleet.tsx renders no .msg-error outside the idle-only expression");
});
```

1. In `Fleet.tsx`, the `{status === "idle" && …}` expression contains `Confirm retire` and does not contain `msg-error`, and the file contains `msg-error` outside that expression (the test above).
2. The three existing tests in the file still pass unchanged.
3. Checked by the reviewer on a render: a retire is refused, then the snapshot shows the ship `assigned` — the message is still in that ship's `.fleet-ship`, with no retire control. The same holds when the snapshot arrives before the refusal.
