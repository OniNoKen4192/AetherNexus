## Objective
An opened moon shows an action bar with exactly the actions the server says are available, each wired to its HTTP command, so the owner can launch, inspect, dock, reply, drop, park, cancel and answer from the browser.

## Context
The Bridge is a Preact page (sources in `web/src`, built by Vite into `dist/web`) served by `nexus serve`. The page computes no state of its own and decides nothing: the server sends, per moon, the list of actions that are valid right now (`detail.actions`), and the page renders one control per entry and nothing else. A command's effect is never applied locally; the event feed brings the new state and the store re-fetches. The server refuses invalid commands with a message (HTTP 409 and others), which the page shows next to the control that sent it. This task also produces the small `useCommand` hook that the two following tasks reuse for their own controls. Components cannot be rendered under `node --test`, so the machine check is the type check, the build, and a test of the built bundle's copy; a person checks the behaviour in a browser later. Affected workflow IDs is `none` because this project has no review suite.

## Interfaces

Produced:

```tsx
// web/src/components/ActionBar.tsx
export function ActionBar({ b }: { b: Bridge })

/** One control's request state. `send` resolves true when the server accepted the command. */
export function useCommand(b: Bridge): {
  busy: boolean;                 // true from send() until its result arrives
  error: string | null;          // the server's message from the last failed send; cleared when the next send starts
  send(name: string, body: object): Promise<boolean>;
  clear(): void;                 // drop the error
};
```

Consumed (exact current code; do not change it):

```ts
// web/src/store.ts
export type Bridge = {
  snapshot: Snapshot | null; conn: "loading" | "live" | "reconnecting";
  systemId: string | null; taskId: string | null;
  detail: MoonDetail | null; activity: FeedEvent[];
  selectSystem(id: string): void; openMoon(taskId: string | null): void;
  run(name: string, body: object): Promise<CommandResult>;   // never throws; no optimistic update
};
// web/src/api.ts
export type CommandResult =
  | { ok: true; status: 200 | 202; data: unknown }
  | { ok: false; status: number; message: string; details?: unknown };
// web/src/types.ts
export type Action = "launch" | "inspect" | "dock" | "reply" | "drop" | "park_stale" | "cancel" | "answer";
export type MoonDetail = {
  moon: Row; spec: string | null;
  voyages: (Row & { owner: Owner | null })[];   // oldest first; fields id: string, status: string, role: string, owner
  verdicts: Row[]; events: FeedEvent[];
  decisions: Row[];                              // this moon's pending decisions, oldest first
  actions: Action[];
};
// snapshot.roles: { implement: string[]; review: string[] }   — provider ids, in routing order
```

A decision row at runtime (typed `Row`; narrow before use):

```ts
{ id: number; kind: string; target_id: string; reasoning: string | null }
// kind "main_tree_changed": reasoning is a JSON string
//   { voyage_id: string; head_before: string; head_after: string; appeared: string[]; vanished: string[] }
//   (appeared / vanished are repository paths). Parse it defensively: if it is not that JSON, show the raw text.
// every other kind ("reject", "adrift", "gate_failed", "restricted", …): reasoning is plain text.
```

The HTTP commands and their JSON bodies (the server rejects unknown or missing fields):

| Command | Body |
|---|---|
| `moon.launch` | `{ taskId, provider? }` |
| `voyage.inspect` | `{ taskId, provider? }` |
| `voyage.dock` | `{ taskId }` |
| `voyage.cancel` | `{ voyageId }` |
| `moon.reply` | `{ taskId, note }` |
| `moon.drop` | `{ taskId }` |
| `moon.park` | `{ taskId, reason }` |
| `decision.answer` | `{ decisionId: number, answer: "mine" \| "not_mine" }` |

Optional fields are omitted from the body when not chosen (never sent as `""` or `null`); string fields must be non-empty.

## Constraints
- `ActionBar` renders nothing when `b.detail` is null. `MoonDetail` mounts it above the tabs.
- **One carried fix in `MoonDetail.tsx`** (found in the review of V0.5-BRIDGE.13): an activity log that mounts without a click on the Activity tab — for example when the open moon's row is clicked again and its detail reloads — must follow the bottom. Add, declared before the existing layout effect that scrolls the log, exactly: `useLayoutEffect(() => { if (activityLog.current === null) followBottom.current = true; });` (`activityLog` and `followBottom` are the refs already in the file; if the log's ref has another name, use that name). Change nothing else about the scrolling.
- **Pending decisions first.** Above the controls, each entry of `detail.decisions` is shown with its kind in a `.badge` and its reasoning as text (for `main_tree_changed`, the parsed lists described under `answer` below instead of the raw JSON).
- **Exactly the server's actions.** One control group per entry of `detail.actions`, in the order given, and no control for an action that is not in the list. With an empty list, no controls are rendered.

| Action | Control | Command and body |
|---|---|---|
| `launch` | a provider `<select>` whose first option is `default order` (no provider) followed by `snapshot.roles.implement`, and a `Launch` button | `moon.launch` `{ taskId }` plus `provider` when one is chosen |
| `inspect` | the same select over `snapshot.roles.review`, and an `Inspect` button | `voyage.inspect` `{ taskId }` plus `provider` when chosen |
| `dock` | a `Dock` button | `voyage.dock` `{ taskId }` |
| `reply` | a note `<textarea>` and a `Reply` button, disabled while the trimmed note is empty; the note is cleared after an accepted send | `moon.reply` `{ taskId, note }` |
| `drop` | a `Drop` button (`.btn.danger`); clicking it reveals, inline, the text `Drop <task id>? This deletes its worktree and branch.` with `Confirm drop` (`.btn.danger`) and `Keep` buttons; only `Confirm drop` sends | `moon.drop` `{ taskId }` |
| `park_stale` | a reason `<input>` and a `Park stale` button, disabled while the trimmed reason is empty | `moon.park` `{ taskId, reason }` |
| `cancel` | a `Cancel voyage` button; the voyage is the last entry of `detail.voyages` whose `status` is `launched` or `working`; with no such voyage the button is disabled | `voyage.cancel` `{ voyageId }` |
| `answer` | for the pending `main_tree_changed` decision: the heading `The main tree changed during this voyage.`, the `appeared` and `vanished` paths as two lists (a list with no paths is omitted), then `That was me` and `Not me` buttons | `decision.answer` `{ decisionId, answer: "mine" }` / `{ decisionId, answer: "not_mine" }` |

- `taskId` in every body is `b.taskId`. Text inputs are sent trimmed.
- **The control rule** (each control group has its own `useCommand`): every button and field of a group is disabled while that group's request is in flight; a failed result's `message` is shown in a `.msg-error` inside that group and stays until that group's next send starts; an accepted send shows nothing. Nothing is updated optimistically: the page does not alter `detail`, `snapshot` or the action list itself.
- `useCommand` calls `b.run` and nothing else; it does not call `fetch`. It must not set state after its component has unmounted.
- Local state is view state only (field text, chosen provider, the open drop confirmation, per-group busy and error). All of it resets when `b.taskId` changes.
- No browser dialogs: no `confirm(`, `alert(` or `prompt(` anywhere in the Touch files.
- `web/src/style.css`: add rules only, below the existing ones; do not edit or remove an existing rule. Use the existing classes (`.btn`, `.btn.danger`, `.field`, `.badge`, `.msg-error`) and colour variables; add no new colours, fonts or external resources.
- Keys on every list rendered from an array. Text is rendered as text (no `dangerouslySetInnerHTML`).
- No new dependencies. TypeScript strict; `npm run build:web` prints no errors.
- The test reads the built bundle from `dist/web/assets/*.js` read-only: it never passes `dist/web` to `startWorld` (that helper deletes its web root on close) and never writes under `dist/`. It fails with a clear message when `dist/web/assets` is missing.
