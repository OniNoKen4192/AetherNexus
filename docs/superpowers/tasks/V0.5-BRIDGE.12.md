## Objective
The Bridge page's header and its three left-column panels (Decisions, Fleet, Routing) show the server's snapshot, read-only, replacing the four placeholder components.

## Context
The Bridge is a Preact page (sources in `web/src`, built by Vite into `dist/web`) served by `nexus serve`. Task 11 landed the build, the data layer and the shell with six placeholder components; this task fills four of them. The page computes no state of its own: every component receives the `Bridge` object and renders what the server last said. This task adds no buttons that change anything; later tasks add actions (ship retire and routing reorder arrive in V0.5-BRIDGE.16, so keep the Fleet and Routing markup simple to extend). Components cannot be rendered under `node --test` (Node does not run TSX and there is no DOM), so the machine check is the type check, the build, and a test that the fixed copy below is present in the built bundle; a person checks the rendering in a browser later. Affected workflow IDs is `none` because this project has no review suite.

## Constraints
- Every component, while `b.snapshot` is null, renders its `.panel` with its title and the text `Loading`. No component throws on a null snapshot.
- **Header** (a `.panel`): shows `snapshot.repo`; the text `rung: <snapshot.rung>`; the text `in flight <limits.in_flight>/<limits.max_concurrent_ships>`; and a connection indicator whose visible text is exactly `b.conn` (`loading`, `live` or `reconnecting`) in a `.badge`, coloured `--ok` when live and `--warn` otherwise. While the snapshot is null the header still shows the connection indicator.
- **Decisions** (title `Decisions`): one `.row` per entry of `snapshot.decisions`, in the order given. Each row shows the decision's `kind` in a `.badge` and its `target_id`; `reasoning`, when not null, is the row's `title` attribute. Clicking a row calls `b.openMoon(target_id)`. The row whose `target_id` equals `b.taskId` also carries `selected`. With no decisions the panel shows exactly `No decisions waiting.`
- **Fleet** (title `Fleet`): ships grouped by `fleet`, one group per provider in the order first seen; under each provider one line per ship class in the order first seen, showing the class name and its counts by status, for example `freighter  2 idle, 1 assigned`. Statuses are listed in the order first seen for that class; a status with a zero count is not listed. With no ships the panel shows exactly `No ships.`
- **Routing** (title `Routing`): two ordered lists (`<ol>`), headed `Implement order` and `Review order`, listing `snapshot.roles.implement` and `snapshot.roles.review` in the order given.
- All values come from `b`; no component calls `fetch`, opens a feed, or keeps server data in its own state. No component calls `b.run` in this task.
- `web/src/style.css`: add rules only, below the existing ones; do not edit or remove an existing rule. Use the existing colour variables; add no new colours, fonts or external resources.
- Keys on every list rendered from an array. Text is rendered as text (no `dangerouslySetInnerHTML`).
- No new dependencies. TypeScript strict; `npm run build:web` (type check, then Vite build) prints no errors.
- The test reads the built bundle from `dist/web/assets/*.js` read-only: it never passes `dist/web` to `startWorld` (that helper deletes its web root on close) and never writes under `dist/`. It fails with a clear message when `dist/web/assets` is missing.
