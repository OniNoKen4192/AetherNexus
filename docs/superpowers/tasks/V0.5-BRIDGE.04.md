## Objective
A command function `setRoleOrder` reorders the providers of one role in `.nexus/config.json` on disk, validating before it writes, and the config schema accepts an optional `server.port` that defaults to `7341`.

## Context
Aether Nexus is getting a long-running server with a browser page (v0.5 "Bridge"). The page lets the owner reorder which provider is tried first for a role; this task is the command function behind that control, with no HTTP or CLI wiring (later tasks add those). The owner may hand-edit `.nexus/config.json` while a server holds an older copy in memory, so the edit must start from the file on disk, never from `g.config`. Voyages in flight check the owner's working tree for foreign changes; the system announces its own writes with `recordTreeWrite` BEFORE writing so they are not mistaken for one. Affected workflow IDs is `none` because this project has no review suite.

## Constraints
- `setRoleOrder` steps, in this order:
  1. Read and JSON-parse `<g.repoRoot>/.nexus/config.json` from disk. Do not use `g.config` as the source. Unparseable JSON refuses with a message naming `.nexus/config.json`.
  2. The current list is the file's `roles[role]`; if the file has no `roles` block or no entry for the role, it is `normalizeConfig(file).roles[role]`.
  3. `order` must be a permutation of the current list (same members, same length, no repeats), else `Refusal("order must contain exactly the providers listed for '<role>': a, b")` where `a, b` is the current list joined with `", "`.
  4. Build the candidate: the parsed file with `roles[role]` replaced (create the `roles` block if absent, filling the other role from step 2's rule so the file stays valid).
  5. `validateConfig(candidate)`; a non-empty result refuses with the errors joined by `"; "`. This also covers a file that was already invalid on disk.
  6. `recordTreeWrite(g, [".nexus/config.json"])`.
  7. Write atomically: a temp file in the same directory, then rename over `config.json`. Format `JSON.stringify(candidate, null, 2) + "\n"`, as `src/server/commands/init.ts` writes it.
  8. `g.config = normalizeConfig(candidate)`; return `{ roles: g.config.roles }`.
- Every other key and value in the file is preserved as it was on disk.
- No new dependencies. Node ≥ 22.13, ES modules, TypeScript strict; follow the style of `src/server/commands/park.ts`.
- Tests use `node:test` and `node:assert/strict`, import compiled code from `dist/`, and clean up their temp repos.

## Acceptance

**Test command (must exit 0):**
```bash
npm test -- "tests/server/config-roles.test.mjs" "tests/config/schema.test.mjs"
```

**Behavioral criteria** (each must be covered by a test in this task):
1. Reordering `["fake","fake2"]` to `["fake2","fake"]` is written to disk, and the next launch with no provider named produces a voyage whose `provider` is `fake2`.
2. An `order` that adds, drops or repeats a provider refuses with the message in Constraints step 3, and the file's bytes are unchanged.
3. A hand edit made after the galaxy was opened survives: rewrite `config.json` on disk with `automation.max_fix_rounds` 5, call `setRoleOrder`, and the file still has 5 and `g.config.automation.max_fix_rounds === 5`.
4. An invalid file on disk (for example `roles.implement` naming an unknown provider elsewhere in the list, or a wrong-typed field) refuses with the validator's message and the file's bytes are unchanged.
5. `setRoleOrder` called in the middle of a voyage (stub adapter callback) leaves no pending `main_tree_changed` decision afterwards.
6. A config without a `server` block normalizes to `server.port === 7341`; `server: { port: 8000 }` is kept; `server: { port: "x" }` and `server: { port: 1.5 }` fail validation.
7. No temp file is left in `.nexus/` after a successful or a refused call.
