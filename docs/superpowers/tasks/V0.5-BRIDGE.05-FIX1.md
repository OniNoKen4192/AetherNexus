## Objective
`nexus events --follow` in table mode (no `--json`) prints the table header line at most once per process, immediately before the first row it prints; every later batch prints row lines only. Today it prints the header `id  ts  kind  moon  payload` again before every delivered batch, so each live event arrives as a header line plus a row line.

## Context
This is fix round 1 for task V0.5-BRIDGE.05, whose spec says table mode "prints rows in the same row format `nexus events` uses". The current `events` case in `src/cli/run.ts` calls `console.log(eventsTable(selected))` for every batch, and `eventsTable` always emits a header as its first line. Everything else in V0.5-BRIDGE.05 passed review and must not change: `followEvents`, the statements, `--json` output, `--since`, `--moon`, the keepalive and the SIGINT handling. Column widths being recomputed per batch is accepted and is not part of this fix. `eventsTable` and `src/cli/format.ts` must not change, so the header is dropped in `run.ts`: the first line of `eventsTable`'s output is always the header, and no cell contains a newline. Affected workflow IDs is `none` because this project has no review suite.

## Interfaces
```text
CLI:  nexus events --follow [--since <id>] [--moon <id>]        (table mode, i.e. without --json)
  The header line (the first line eventsTable returns) is printed at most once per process,
  immediately before the first row line printed.
  Each later non-empty (post --moon filter) batch prints only eventsTable's row lines for that batch.
  A batch that is empty after filtering prints nothing and does not consume the header.
  If no row is ever printed, no header is printed.
  --json mode: unchanged (one compact JSON object per line, no header).
```
No signature changes anywhere.
