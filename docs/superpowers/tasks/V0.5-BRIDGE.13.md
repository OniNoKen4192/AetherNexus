## Objective
The Bridge page's right column shows the selected system (planets and moons) and, for an opened moon, a detail panel with spec, activity, audit and verdict tabs — read-only, replacing the two placeholder components.

## Context
The Bridge is a Preact page (sources in `web/src`, built by Vite into `dist/web`) served by `nexus serve`. Task 11 landed the build, the data layer and the shell; Task 12 filled the header and left column. The page computes no state of its own: components receive the `Bridge` object and render what the server last said. The only local state allowed here is view state (which tab is open, whether the reader has scrolled up). This task adds no control that changes anything on the server; later tasks add an action bar inside the moon detail (V0.5-BRIDGE.14), new-system and assign forms inside the system view (V0.5-BRIDGE.15) and failure notices on moon rows (V0.5-BRIDGE.16), so keep the markup simple to extend. Components cannot be rendered under `node --test` (no TSX, no DOM), so the machine check is the type check, the build, and a test that the fixed copy below is present in the built bundle; a person checks the rendering in a browser later. Affected workflow IDs is `none` because this project has no review suite.

## Constraints
- **SystemView** (a `.panel`, title `System`):
  - While `b.snapshot` is null: the title and the text `Loading`.
  - With no systems: exactly `No systems yet.`
  - A system picker: a `<select className="field">` with one option per system (label: the title when not null, else the id), whose value is `b.systemId` and whose change calls `b.selectSystem(<id>)`.
  - The system shown is the one whose id equals `b.systemId`. Its planets are listed in the order given, each with its name; under each planet its moons in the order given.
  - A moon with a non-null `task_id` is a `.row` showing the moon name, the task id and the status in a `.badge`; clicking it calls `b.openMoon(task_id)`; the row whose `task_id` equals `b.taskId` also carries `selected`.
  - A moon whose `body_status` is `barren` shows its name and the word `barren`, is not a `.row`, and has no click handler. A planet whose `body_status` is `barren` shows `barren` beside its name.
- **MoonDetail**:
  - Renders nothing (`null`) when `b.taskId` is null.
  - Otherwise a `.panel` with a `Close` button (`.btn`) that calls `b.openMoon(null)`, present in every state below.
  - When `useBridgeStatus().detailError` is not null: that message in a `.msg-error`. When `b.detail` is null and there is no error: the text `Loading`.
  - With a detail: the moon's name, task id, status in a `.badge`, and `round <n>`; `park_reason`, when not null, on its own line.
  - Four tabs (`.tabs`, `.tab`, `.tab.active`), labelled `Spec`, `Activity`, `Audit`, `Verdicts`; `Spec` is open first; the open tab is view state and resets to `Spec` when `b.taskId` changes.
  - **Spec**: `detail.spec` in a `.log` (preformatted text); when null, exactly `No spec file.`
  - **Activity**: `detail.events` followed by `b.activity`, de-duplicated by event `id`, ordered by `id` ascending (newest at the bottom), one line per event inside a single `.log`. A line is `<ts> <kind> <summary>`: for a `voyage.event` row the kind is `payload.event.kind` and the summary is `JSON.stringify(payload.event.data)`; for any other row the kind is the row's `kind` and the summary is `JSON.stringify(payload)`. With no events: exactly `No activity yet.`
  - The activity log follows the bottom: after an update it is scrolled to the bottom, unless the reader had scrolled up (the log was not within 24 px of the bottom before the update), in which case its scroll position is left alone.
  - **Audit**: the `payload.audit` of the last `voyage.audited` row among the same merged events, as `JSON.stringify(audit, null, 2)` in a `.log`; when there is none, exactly `No audit yet.`
  - **Verdicts**: `detail.verdicts` in the order given, each showing `round <n>`, the verdict in a `.badge`, the reasoning as text, and `delta_spec` in a `.log` when not null. With none: exactly `No verdicts yet.`
- All server data comes from `b` and `useBridgeStatus()`; no component calls `fetch`, opens a feed, or copies server data into its own state. No component calls `b.run` in this task.
- `web/src/style.css`: add rules only, below the existing ones; do not edit or remove an existing rule. Use the existing colour variables; add no new colours, fonts or external resources.
- Keys on every list rendered from an array. Text is rendered as text (no `dangerouslySetInnerHTML`).
- No new dependencies. TypeScript strict; `npm run build:web` prints no errors.
- The test reads the built bundle from `dist/web/assets/*.js` read-only: it never passes `dist/web` to `startWorld` (that helper deletes its web root on close) and never writes under `dist/`. It fails with a clear message when `dist/web/assets` is missing.
