## Objective
A poller `followEvents` delivers every event appended to the SQLite event log after a cursor, in order, including events appended by other processes, and `nexus events --follow` prints events as they arrive until interrupted.

## Context
Aether Nexus keeps an append-only event log in SQLite that several processes write to (a server and the CLI). v0.5 adds a live feed to a browser; this task builds the one poller that both the feed (a later task) and the CLI use, so there is a single implementation of "tail the log". Polling is deliberate: SQLite gives no cross-process notification, and a 250 ms poll over an indexed primary key is cheap. `nexus events --follow` refuses today with a "arrives with the daemon" message; this task makes it work. Affected workflow IDs is `none` because this project has no review suite.

## Interfaces

Produced:

```ts
// src/db/statements.ts  (added to STATEMENTS; SQL lives only in this file)
"events.page":  "SELECT * FROM events WHERE id > @id ORDER BY id LIMIT @limit",
"events.maxId": "SELECT COALESCE(MAX(id), 0) AS id FROM events",

// src/server/follow.ts
export function followEvents(
  db: NexusDb,
  opts: { since: number; pollMs: number; onEvents: (rows: EventRow[]) => void },
): { cursor(): number; stop(): void };
// Delivers every event with id > since, in ascending id order, each exactly once.
// Reads in pages of at most 500 rows; one onEvents call per non-empty page; drains all pages before waiting.
// The first read happens synchronously inside the followEvents call.
// The timer is unref'd, so a follower alone never keeps the process alive.
// cursor() is the id of the last delivered event (or `since` if none). After stop(), onEvents is never called again.
```

```text
CLI:  nexus events --follow [--since <id>] [--moon <id>] [--json]
  Without --since, starts at 0 (prints the existing log, then follows), matching `nexus events` today.
  Table mode prints rows in the same row format `nexus events` uses; --json prints one JSON object per line.
  --moon filters rows to that moon id.
  Runs until SIGINT, then exits 0.
```

## Constraints
- All SQL goes in `src/db/statements.ts` as named statements (`tests/db/registry.test.mjs` enforces this).
- `followEvents` does synchronous reads on a timer; it must not overlap its own polls and must not throw into the timer if `onEvents` throws (let the error surface once to stderr and keep following).
- In `src/cli/run.ts`, replace the `--follow` refusal in the `events` case and the `(--follow arrives with the daemon)` note in `USAGE`. The CLI case stays a thin wrapper: no polling logic in `run.ts` beyond calling `followEvents`, printing, and waiting for SIGINT. On Windows, SIGINT delivered by `child.kill("SIGINT")` terminates the process without running handlers; the test must not depend on a graceful exit code there (kill the child and assert on the lines read).
- No new dependencies. Node ≥ 22.13, ES modules, TypeScript strict.
- Tests use `node:test` and `node:assert/strict`, import compiled code from `dist/`, wait on conditions with a bounded timeout rather than fixed sleeps, and clean up temp repos and child processes even when an assertion fails.

**Behavioral criteria** (each must be covered by a test in this task):
1. With 1200 events in the log, following from 0 with `pollMs` 20 delivers ids strictly ascending with none missing or repeated, in more than one `onEvents` call, none larger than 500 rows; an event appended afterwards arrives; after `stop()` a further append is not delivered.
2. An event appended through a second `openDb` handle on the same file is delivered.
3. `since` equal to the current maximum id delivers nothing until something is appended, then delivers exactly that event.
4. The first page is delivered before `followEvents` returns.
5. `cursor()` equals the id of the last delivered event.
6. `nexus events --follow --json`, spawned as a child process in a galaxy, prints one JSON line for an event the test process appends after the child started.
7. `nexus events` without `--follow` behaves as before (existing CLI tests pass unchanged).
