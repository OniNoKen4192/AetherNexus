## Objective
The owner can retire an idle ship and reorder the providers of a role from the page, and a voyage that failed on the server is visible on its moon's row and at the top of its moon detail.

## Context
The Bridge is a Preact page (sources in `web/src`, built by Vite into `dist/web`) served by `nexus serve`. The page decides nothing and applies nothing locally: a control sends a command, the server accepts or refuses it with a message, and the event feed brings the new state. Earlier tasks built the read-only Fleet and Routing panels (Task 12), the system view and moon detail (Task 13), the action bar and the `useCommand` hook (Task 14) and the create and assign forms (Task 15). When a voyage the server was running ends in an unexpected error, the server keeps a short record of it and sends the records as `snapshot.failures`; without this task the owner would see a moon stop with no explanation. Components cannot be rendered under `node --test`, so the machine check is the type check, the build, and a test of the built bundle's copy; a person checks the behaviour in a browser later. Affected workflow IDs is `none` because this project has no review suite.

## Constraints
- **Fleet**: keep the per-provider, per-class count lines from Task 12. Under each provider, also list its ships in the order given: name, class, and status in a `.badge`. A ship whose status is `idle` has a `Retire` button; clicking it reveals, inline, a `reason` input with `Confirm retire` (`.btn.danger`) and `Cancel` buttons; `Confirm retire` is disabled while the trimmed reason is empty and sends `fleet.retire` with the ship's id and the trimmed reason. When accepted, the inline form closes. Ships in any other status have no Retire control.
- **Routing**: each provider in each of the two lists has an `Up` and a `Down` button (visible text exactly `Up` and `Down`; each also carries an `aria-label` naming the provider, for example `Move codex up`). `Up` on the first entry and `Down` on the last are disabled. A click sends `config.roles` with that role and the list with the provider swapped one place in that direction. A list with one provider shows both buttons disabled.
- **Failures in SystemView**: a moon row whose `task_id` has at least one entry in `snapshot.failures` also shows a `failed` marker in a `.badge` coloured `--danger`, with the latest such failure's `message` as its `title` attribute.
- **Failures in MoonDetail**: at the top of the panel (below the `Close` control, above the action bar), every entry of `snapshot.failures` whose `taskId` equals `b.taskId`, newest first, each in a `.msg-error` showing its `ts` and `message`. Shown whether or not the detail has loaded.
- **The control rule**: each provider's ship list entry with an open retire form, and each of the two routing lists, has its own `useCommand`. Every button and field of that group is disabled while its request is in flight (for a routing list: all `Up` and `Down` buttons of that list); a failed result's message is shown in a `.msg-error` inside that group and stays until that group's next send starts; nothing is updated optimistically — the page does not reorder the list or change a ship's status itself.
- All server data comes from `b`; no component calls `fetch` or copies server data into its own state. Local state is view state only (which retire form is open, the reason text).
- No browser dialogs: no `confirm(`, `alert(` or `prompt(` anywhere in the Touch files.
- `web/src/style.css`: add rules only, below the existing ones; do not edit or remove an existing rule. Use the existing classes and colour variables; add no new colours, fonts or external resources.
- Keys on every list rendered from an array. Text is rendered as text (no `dangerouslySetInnerHTML`).
- Everything the four components already show stays as it is; the existing `tests/http/page-*.test.mjs` tests still pass unchanged.
- No new dependencies. TypeScript strict; `npm run build:web` prints no errors.
- The test reads the built bundle from `dist/web/assets/*.js` read-only: it never passes `dist/web` to `startWorld` (that helper deletes its web root on close) and never writes under `dist/`. It fails with a clear message when `dist/web/assets` is missing.
