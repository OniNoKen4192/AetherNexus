## Objective
In `tests/e2e/bridge.test.mjs`, the second moon (E2) is released from its test-side latch before `moon.reply` is sent, so E2's voyage has already ended when the reply writes E1's spec into the main tree. The "no `main_tree_changed` decision" assertion therefore passes even if the server stops exempting its own spec write. After this fix, E2's voyage is provably in flight across the reply, and the test fails if the reply's write is not exempt.

## Context
This is fix round 1 for task V0.5-BRIDGE.10. The server compares the main tree against its state at launch when a voyage ends (`src/server/dispatch.ts`, end of `runVoyage`) and opens a `main_tree_changed` decision for anything that appeared. Paths recorded by `tree.written` events after that launch are exempt; `moon.reply` records one for the spec it amends (`src/server/commands/park.ts`). The check is only exercised if a voyage launched before the reply ends after it. The existing latch (`e2Gate` / `releaseE2` / `holdE2`) is the right mechanism; only where it is released, and what is asserted around it, is wrong. The product is correct: a reviewer-side variant with the release moved passes. Do not change product code. Affected workflow IDs is `none` because this project has no review suite.
