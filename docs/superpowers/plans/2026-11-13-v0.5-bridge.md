# Aether Nexus v0.5 — the Bridge — Implementation Plan

> **For agentic workers:** this plan is lane-tagged for Lanes (`.lanes/config.json`). Run it with `/lanes-run`: DELEGATE tasks are emitted as specs and dispatched; KEEP tasks use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A long-running server per galaxy plus a browser page from which the whole manual moon lifecycle is driven, with the CLI still fully working on its own.

**Architecture:** The server is one more process calling the existing command functions in `src/server/commands/`; it and the CLI both write to SQLite directly. The browser reads a snapshot, tails the event log over server-sent events, and POSTs commands. Limits and the main-tree question live in the event log and database, never in server memory, so they hold across processes.

**Tech Stack:** Node ≥ 22.13, TypeScript, `node:sqlite`, `node:http`, `node:async_hooks`; Preact + Vite (dev dependencies only); tests with `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-13-v0.5-bridge-design.md` (read it first; section numbers below refer to it).

## Global Constraints

- No new **runtime** dependencies. `preact`, `vite`, `@preact/preset-vite` are devDependencies.
- Every state change is an appended event with a reducer; after any test scenario `rebuild` must leave `dumpProjections` byte-equal.
- `Git` (`src/core/git.ts`) stays the only caller of git from `src/server/`.
- HTTP handlers and CLI cases are thin wrappers; behaviour lives in `src/server/commands/`.
- Every existing CLI command keeps its behaviour, with or without a server running. The server never acts without a human request.
- SQL lives only in `src/db/statements.ts` (see `tests/db/registry.test.mjs`); add named statements there.
- Tests import from `dist/`; `npm test` builds first. Run one area with `npm test -- "tests/<dir>/*.test.mjs"`.
- Server binds `127.0.0.1` only. Default port `7341`. Cookie name `nexus_token`. Feed poll `250` ms, heartbeat `15000` ms.
- Each task lands as one commit on branch `design/v0.5-bridge` (a DELEGATE task is committed in its worktree and merged by the Lanes controller, using the task's commit message). End commit messages with `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.

## Review Focus

1. **Server killed hard mid-voyage.** On the next start the voyage must show as stale and be parkable, not hang the moon or silently hold a concurrency slot forever. Test in Task 7.
2. **Malformed requests.** Invalid JSON, an unknown command name, a missing field or a 2 MB body must get 400/404/413, never a crash or a 500. Test in Task 9.
3. **The same action clicked twice** (two tabs). The second dock/reply/answer gets a 409 with a message, never a 500 and never a second effect. Test in Task 9.
4. **Config edited by hand while the server runs.** A routing edit must start from the file on disk, not the server's copy, and must refuse without writing if the file is invalid. Test in Task 4.
5. **A long backlog on connect.** A browser connecting with `since=0` to a log of thousands of events must receive all of them in order, then go live with no gap or duplicate. Test in Task 8.

### Task 3: The main-tree question (spec 5.3) (LANE: KEEP)

**Files:** Create `src/server/commands/decision.ts`, `tests/server/tree.test.mjs`. **Interfaces — Produces:**
- Event kind `tree.written`, payload `{ paths: string[] }` (repo-relative, forward slashes), no envelope ids, reducer that does nothing.
- `recordTreeWrite(g: Galaxy, paths: string[]): void` exported from `dispatch.ts`; call it **before** writing the file.
- Decision kind `main_tree_changed`, `target_kind: "moon"`, `target_id: <task id>`, `reasoning`: the JSON string `{ voyage_id, head_before, head_after, appeared, vanished }`.
- From `decision.ts`:
  - `pendingTreeDecision(g: Galaxy, taskId: string): { id: number; reasoning: string } | undefined`
  - `requireTreeAnswered(g: Galaxy, taskId: string): void` — throws `Refusal("moon <task> has an unanswered main-tree question (decision <id>) — answer it first: nexus decision answer <id> --mine | --not-mine")`.
  - `answerDecision(g: Galaxy, input: { decisionId: number; answer: "mine" | "not_mine" }): { moonStatus: MoonStatus; parked: boolean }`
- Statement `events.kindSince`: `SELECT * FROM events WHERE kind = @kind AND id > @id ORDER BY id`.
- CLI: `nexus decision answer <decision-id> --mine | --not-mine`.

**Behaviour:**
- `runVoyage`, where it parks today: compute `appeared` and `vanished`, remove from `appeared` every path named by `tree.written` events with id greater than this voyage's `voyage.launched` event id. If HEAD is unchanged and both lists are empty, the tree is unchanged. Otherwise open the decision and **continue as if unchanged** (`out.done` is kept).
- `requireTreeAnswered` is the first check in `launchMoon`, `inspectMoon`, `dockMoon` and `replyMoon`. `dropMoon` is unchanged (its `resolveDecisions` closes the question with outcome `drop`). `replyMoon` calls `recordTreeWrite(g, [moon.spec_path])` before writing the spec.
- `answerDecision`: refuse a missing decision, a resolved one, or one whose kind is not `main_tree_changed` (`decision <id> is a '<kind>' decision — use reply or drop`). Append `decision.resolved` with outcome `mine` or `not_mine`. For `not_mine`, then:
  1. moon `adrift` or `quarantined` → nothing more, `parked: false`;
  2. else if the latest implement voyage of the assignment is `holding` or `cleared` → `parkVoyage` with reason `main_tree_modified` and the decision's reasoning as details, `parked: true`;
  3. else → append `moon.adrift` (reason `main_tree_modified`) and an `adrift` `decision.opened`, as `launch.ts:158-159` does, `parked: true`.

### Task 6: Server core — listen, lock, access control, `nexus serve` (LANE: KEEP)

**Files:** Create `src/server/lock.ts`, `src/server/http/server.ts`, `src/server/http/auth.ts`, `tests/http/helpers.mjs`, `tests/http/access.test.mjs`. Modify `src/cli/run.ts`, `src/server/commands/init.ts` (add `server.json` to the generated `.nexus/.gitignore`).

**Interfaces — Produces:**
- `acquireServerLock(g: Galaxy, info: { port: number }): { release(): void }` — writes `.nexus/server.json` `{ pid, port, started }`; if the file names a live pid, `Refusal("a server for this galaxy is already running (pid <n>, port <p>)")`; a dead pid's file is replaced. Adds `.nexus/server.json` to `.git/info/exclude` if absent (the way `initGalaxy` adds the worktrees line), so the file never appears in `git status`.

- Other GETs serve static files from `webRoot` with path traversal refused; if `webRoot` has no `index.html`, `/` answers `503` with the text `the page is not built — run npm run build`.
- `GET /api/ping` → `200 { ok: true }` (lets this task be tested before later tasks add routes).
- `nexus serve [--port <n>]`: open the galaxy, start, print `Bridge: <url>` and `Ctrl-C to stop`, wait for SIGINT/SIGTERM, `close()`, exit 0. `close()` releases the lock.
